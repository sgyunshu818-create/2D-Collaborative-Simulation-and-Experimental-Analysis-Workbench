# 二维协同仿真与实验分析工作台 · 使用说明

本工作台用于创建二维仿真场景、配置单位和任务路线、观察运行过程，并对保存的结果进行回放、比较和导出。支持坦克、装甲车、飞机、无人机四类装备，提供广域山区地图、世界地图和已有图像实验结果浏览。

第一次使用，可先按第 1、2 节完成一次示例运行，再学习场景编辑与结果分析。

## 1. 安装与启动

### 1.1 首次安装

以下步骤以 Windows 和 PowerShell 为例。使用带 Tcl/Tk 的 Python 3.11；Tcl/Tk 是工作台界面的运行组件。本文将包含 `README.md`、`requirements.txt` 和 `sim_app` 文件夹的目录称为**项目根目录**。

可以从 GitHub 下载并解压源码 ZIP，或者使用 Git 获取：

```powershell
git clone https://github.com/sgyunshu818-create/-.git simulation-workbench
cd simulation-workbench
```

1. 获取完整项目后，进入项目根目录；本地工作目录可能名为 `Exp`，从 GitHub 获取时以实际下载目录为准。
2. 在该目录打开 PowerShell。下文所有命令均从此目录执行。
3. 创建运行环境并安装依赖：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

4. 启动工作台：

```powershell
.\.venv\Scripts\python.exe -m sim_app.workbench
```

如果系统使用 `py` 启动器，可将创建环境的命令替换为 `py -3.11 -m venv .venv`。后续命令继续使用 `.venv` 中的解释器，无需激活环境，也无需修改 PowerShell 执行策略。

核心依赖由 `requirements.txt` 指定。安装阶段需要下载依赖，环境准备完成后，内置地图和场景可离线使用。请保留 `sim_app/assets` 中的地图、装备图样和字体文件。

### 1.2 日常启动

已完成安装后，双击 [启动工作台.cmd](启动工作台.cmd) 即可。也可以继续使用上面的启动命令。

默认载入 [广域山区场景](configs/detailed_scene.json)，世界尺寸为 **240000 × 160000 仿真单位**，包含 8 个示例单位。初始视图位于中央河谷；若看不到单位列表或属性栏，点击“恢复面板”。

### 1.3 检查运行环境

打不开窗口时，先在 PowerShell 中执行：

```powershell
.\.venv\Scripts\python.exe -m sim_app.workbench --check
```

此命令检查环境和工作台入口，不进入工作台主界面。错误处理方法见第 10 节。

## 2. 第一次运行示例

这次练习直接使用默认场景中的路线，无需先配置单位。

1. 打开工作台，进入左侧“场景编辑”。
2. 点击“校验”，确认当前场景有效。
3. 点击右上角“保存并运行”。程序保存有效输入，并打开独立仿真窗口；如弹出保存对话框，选择可写目录并填写 `.json` 文件名，例如 `demo_first_run.json`，然后确认保存。
4. 在仿真窗口点击“开始”，或按 **Enter**。只打开窗口不会自动开始运动。
5. 从左侧列表选择一台装备，在右侧查看任务进度、路程和联系人；也可直接单击地图中的装备。
6. 点击“暂停”和“继续”，或按 **Space**，观察时钟和单位运动的变化。浏览地图时可使用滚轮缩放和左键拖动。
7. 等待示例自然结束。默认场景的仿真时间约为 **45 秒**；实际等待时间取决于窗口运行情况。结束后程序自动保存结果，点击“打开结果目录”可查看文件。
8. 关闭仿真窗口，返回工作台的“历史分析”。若新记录尚未出现，点击“刷新”；选中记录查看摘要，并点击“回放记录”重看过程。

工作台和仿真窗口是两个独立窗口。关闭仿真窗口后，仍可在工作台继续编辑和分析；修改编辑器中的草稿也不会改变已经启动的那次运行输入。

## 3. 创建和编辑场景

### 3.1 选择一个起点

可在场景下拉框中选择模板并点击“载入”，也可使用“场景文件 → 打开…”选择 JSON 文件。

| 场景文件 | 适合练习的内容 |
| --- | --- |
| [configs/detailed_scene.json](configs/detailed_scene.json) | 广域山区、四类装备、分区浏览和默认演示路线 |
| [configs/basic_scene.json](configs/basic_scene.json) | 小范围单位、任务点和返航操作 |
| [configs/obstacle_scene.json](configs/obstacle_scene.json) | 矩形障碍与路线运行 |
| [configs/sharing_scene.json](configs/sharing_scene.json) | 单位观测与消息共享 |
| [configs/geographic_scene.json](configs/geographic_scene.json) | 带地理参考的世界地图显示 |
| [configs/mountain_scene.json](configs/mountain_scene.json) | 范围较小的山区地图 |

“场景文件”菜单也可新建空白场景。第一次自行编辑，建议从基础场景开始，保留原有世界尺寸和规则。

### 3.2 认识编辑界面

| 区域 | 用途 |
| --- | --- |
| 左侧对象列表 | 选择单位、任务点和障碍；重叠对象优先从列表选择 |
| 中间地图 | 查看布局、选择对象、拖动编辑或平移视图 |
| 右侧“属性与规则” | 精确修改所选对象，或编辑整个场景的参数 |
| 顶部工具栏 | 载入、撤销、重做、校验、保存及保存并运行 |
| 地图底部工具栏 | 缩放、适应、切换视图、定位装备和选择分区 |

“展开地图”隐藏两侧面板以增加浏览空间；“恢复面板”返回完整编辑布局。

### 3.3 配置单位

从列表或地图选择单位，在右侧修改属性，再点击“应用修改”。

| 属性 | 填写说明 |
| --- | --- |
| 编号 | 用于列表、事件和结果中的身份识别；同一场景内不得重复 |
| 阵营 | 红方或蓝方 |
| 装备类型 | 坦克、装甲车、飞机或无人机；选择后同步更新图样与通行类别 |
| X / Y 坐标 | 场景中的平面位置，需处于世界范围内 |
| 速度 | 仿真单位/秒；留空使用默认值 |
| 观测范围 | 仿真单位；留空使用默认值 |
| 任务后返航 | 完成任务点后，是否继续前往本阵营返航点 |

添加或删除单位可使用对象列表附近的对应按钮。地图上的红蓝轮廓和标签用于区分阵营，装备图样用于区分类型。

**输入表单、应用修改、保存文件是三个不同操作。** 修改后主动点击“应用修改”，确认地图与列表已更新，再校验和保存。校验失败时，根据提示修正具体字段。

### 3.4 设置任务点、障碍和场景规则

**任务点：** 先选择所属单位，再点击添加任务点的按钮；也可在虚拟地图中按住 **Shift** 单击位置。任务点按列表顺序执行。选中任务点后可精确修改坐标，并通过“上移”“下移”调整顺序，或删除多余任务点。

**障碍：** 添加矩形障碍后，配置位置、宽度和高度。障碍必须合法且处于世界范围内。单位的通行由场景中定义的通行类别、障碍和路线决定。

**场景与规则：** 右侧切换到该表单，可修改名称和世界尺寸，并展开出生点、返航点和高级规则。第一次编辑时可保留固定步长等参数，只修改需要验证的内容。缩小世界尺寸不会自动移动或裁剪原有对象，需要重新检查坐标。

虚拟视图中，从对象位置开始拖动可编辑对象；只想浏览地图时，先开启“平移模式”，防止误移动单位或任务点。

### 3.5 实操：保存一条自己的路线

以下例子使用基础场景，所有坐标均在其 900 × 600 的世界范围内。

1. 使用“场景文件 → 打开…”载入 `configs/basic_scene.json`。
2. 在列表选择 `red_ground_01`，将速度改为 **60**，点击“应用修改”。
3. 保留原任务点 **(450, 300)**，再添加一个任务点。选中新任务点，填写 **X = 650、Y = 300**，点击“应用修改”；确认它排在原任务点之后。
4. 在“场景与规则”中把名称改为“基础路线演示”，应用修改。
5. 点击“校验”。如有错误，按提示修正后再次校验。
6. 使用“场景文件 → 另存为…”保存为 `configs/user_scenes/demo_route.json`。
7. 点击“保存并运行”，在新窗口点击“开始”。观察该单位是否按顺序到达两个任务点；若保留“任务后返航”，还会继续返航。

之后可用“场景文件 → 打开…”重新载入 `demo_route.json`，继续修改。模板保存时会生成独立副本；使用“另存为…”可指定自己便于识别的文件名。

## 4. 地图浏览与地理参考

### 4.1 常用浏览操作

| 操作 | 场景编辑器 | 仿真与回放窗口 |
| --- | --- | --- |
| 放大、缩小 | 地图上滚轮，或“− / +”按钮 | 地图上滚轮，或“放大 / 缩小”按钮 |
| 平移 | 空白处左拖；开启“平移模式”后可从对象位置左拖 | 地图内直接左拖 |
| 查看完整虚拟地图 | 点击“适应”；广域图也可选“区域 → 全域总览” | 虚拟视图中点击“复位” |
| 返回单位附近 | 选择单位后点击“定位装备” | 选择单位后点击“定位装备” |
| 增加地图显示空间 | 点击“展开地图” | 点击“展开地图” |
| 恢复列表与属性 | 点击“恢复面板” | 点击“恢复面板” |

滚轮缩放以鼠标所在位置为锚点；按钮缩放以视图中心为锚点。平移和缩放只改变视图，不改变单位坐标或任务路线。

### 4.2 广域山区地图

编辑器底部“区域”菜单可跳转 **25 个地形分区**。“全域总览”查看完整地图，“当前装备区”或“定位装备”返回单位附近；没有选择单位时返回地图中央。

| 地图 | 缩放范围 |
| --- | --- |
| 广域山区地图 | 1×–256× |
| 小范围山区地图 | 1×–64× |
| 基础等小场景 | 1×–6× |
| 世界地图 | 1×–256× |

山区地图包括山脉、峡谷、湖区、河流、村落、农田和机场。高倍缩放用于查看或精确操作，不会增加超出原始图像分辨率的细节。

### 4.3 世界地图与地理参考

地图工具栏可切换世界地图和虚拟场景；运行窗口中的相应按钮为“全球”和“场景”。“全球”展示地球底图，虚拟场景展示本次仿真的局部平面空间。

要在世界地图上正确定位单位和路线，场景必须具有地理参考。可先打开 `configs/geographic_scene.json` 学习，或在“场景与规则 → 地理参考”设置：

- **中心纬度、中心经度：** 场景中心对应的地理位置。
- **每场景单位对应的米数：** 将局部坐标换算为地理距离的比例。

填写后点击“应用地理参考”，再校验、保存。没有地理参考的场景仍可浏览世界底图，但不会自动获得真实经纬度定位。默认广域山区属于虚拟场景，其坐标不能直接当作经纬度或米数。

## 5. 仿真运行与快捷键

### 5.1 运行时看什么

“保存并运行”打开独立窗口后，需要点击“开始”。

- **左侧：** 运行状态、仿真时间、单位列表、场景信息和事件。单位列表可搜索、滚动，事件可按所选单位筛选。
- **地图：** 单位位置、任务路线、运动轨迹及编号；轨迹和编号可独立开关。
- **右侧：** 所选单位的任务进度、累计路程、受阻原因和联系人。较长联系人列表可滚动。
- **底部：** 开始、暂停、继续、重置、退出、导出、打开结果目录和帮助。

暂停期间仿真时钟不推进；继续后不会补算暂停期间的等待时间。任务受阻时，应查看单位原因和事件，再返回编辑器调整路线或障碍。

要取得完整任务结果，等待自然结束后再导出或回放。提前退出、重置或切换场景保存的是当时的运行状态，不能当作完整任务结果。尚未点击开始的窗口通常没有可保存的运行记录。

### 5.2 快捷键

以下快捷键用于**仿真或回放窗口**。先单击该窗口，并让输入焦点离开搜索框；编辑器中的 Space 操作用途不同。

| 按键 | 功能 |
| --- | --- |
| Enter | 开始运行或开始回放 |
| Space | 暂停 / 继续 |
| T | 切换时间倍速（0.5× / 1× / 2× / 4×）；实时运行与回放共用同一档位 |
| R | 重置；普通运行回到初始场景，回放回到首份快照 |
| Esc | 退出当前窗口；已开始的普通运行会尝试先保存 |
| G | 切换到全球地图 |
| V | 切换到虚拟场景 |
| F | 定位场景或所选装备，取决于当前地图视图 |
| M | 展开地图 / 恢复面板 |
| C | 切换内置场景；已开始的普通运行需先暂停或结束，切换前保存当前记录 |
| S | 普通运行中开关消息共享 |
| L | 从当前运行的已保存记录进入回放；运行中需先暂停或结束 |
| ← / → | 回放中查看上一份 / 下一份快照 |
| H | 显示操作帮助 |

## 6. 保存文件与查找结果

### 6.1 场景与结果保存在哪里

下列路径均相对于项目根目录。运行使用自定义输出目录时，以该目录为准。个人场景、运行记录和实验输出在使用后创建，不随 Git 仓库发布。

| 路径 | 内容 |
| --- | --- |
| `configs/` | 内置场景与配置 |
| `configs/user_scenes/` | 自己保存的场景 |
| `configs/user_scenes/run_inputs/` | 工作台启动运行时保存的独立输入副本 |
| `artifacts/runs/run_时间_后缀/` | 一次普通运行的完整输出目录 |
| `artifacts/workbench_logs/` | 工作台启动子窗口的日志 |
| `artifacts/marker_experiment/` | 本地保存的首批图像实验结果，若已执行或导入 |
| `artifacts/marker_repeat5/` | 本地保存的多轮图像实验结果，若已执行或导入 |
| `sim_app/assets/` | 地图、装备图样和字体 |

“保存”或“另存为…”处理的是**场景输入文件**；运行结束、导出结果处理的是**本次运行记录**。保存场景不会自动产生仿真结果。

### 6.2 一次运行的文件

| 文件 | 用途 |
| --- | --- |
| `run.json` | 场景输入、快照、事件与运行信息；历史分析和回放读取此文件 |
| `states.csv` | 各快照中的单位状态，便于表格软件分析 |
| `events.csv` | 控制、观测、任务等事件记录 |
| `run.note.json` | 添加备注后生成，保存备注，不修改原始运行记录 |

自然结束后结果自动保存。也可在运行窗口点击“导出”或“打开结果目录”。若保存失败，先处理目录权限或磁盘空间问题，再重试，避免直接强制结束进程。

备份自己的工作时，保存自建场景文件和整个运行目录。需要回放时至少保留完整的 `run.json`；需要复核导出内容时，也保留两个 CSV。

### 6.3 三类 CSV 的区别

- **运行原始 CSV：** 每次运行目录中的 `states.csv`、`events.csv`，用于检查逐快照状态和逐事件事实。
- **单次结果汇总 CSV：** 在历史分析中选择一条记录后“导出汇总 CSV”，用于查看统一的结果指标。
- **比较 CSV：** 完成两条记录比较后使用同一导出按钮，保存左右结果和差值。

## 7. 历史分析、比较与回放

### 7.1 查找和查看一次运行

1. 进入“历史分析”，点击“刷新”。
2. 根据场景名称、编号或备注筛选，选择一条记录。
3. 查看运行状态、结束原因、时长、完成/受阻/未完成任务、路程及事件数。
4. 需要在表格软件查看时，点击“导出汇总 CSV”并选择文件保存位置。

普通运行目录会自动刷新。其他目录中的记录可通过“导入…”选择 `run.json`，或用“更多 → 选择记录目录…”切换扫描位置。看不到文件所在目录时，可用“更多 → 查看记录目录路径…”确认当前分析的是哪个目录。

“更多 → 编辑所选记录备注…”可添加便于识别的说明，例如“速度 60，两个任务点”。备注独立保存。重开工作台后，磁盘中的运行记录和备注仍可查看。

### 7.2 比较两次运行

一次只改变一个参数，更容易理解差异。可使用第 3.5 节的路线作为例子：

1. 完成速度为 **60** 的“基础路线演示”，在历史中选中该记录，点击“设为左侧”。
2. 点击“复制输入新建”，把该记录使用的场景载入编辑器。
3. 将同一单位 `red_ground_01` 的速度改为 **90**，保留其他单位、任务点和规则，应用修改并校验。
4. 另存为 `configs/user_scenes/demo_route_fast.json`，运行至结束。
5. 回到历史，选择新记录并点击“设为右侧”，再点“比较两条”。也可按住 Ctrl 选择两条记录进行比较。
6. 先看输入差异，确认只修改了预期参数，再看结果指标和时间曲线；按需导出比较 CSV。

所有差值均为 **右侧 − 左侧**。例如时长差为负数，表示右侧运行时间更短。只提高一个单位的速度，总时长不一定变短，其他单位也可能决定结束时间。两条运行曲线保留各自时间轴。

### 7.3 回放与事件定位

在历史中选择记录，点击“回放记录”。回放读取保存的过程，不重新计算一次仿真，也不会改写原始结果。

- 点击“开始”或 Enter 播放，用 Space 暂停和继续。
- 点击时间轴跳到指定快照，跳转后回放暂停。
- 用“上一帧 / 下一帧”按钮或方向键逐快照检查。
- 点击倍率按钮，在 **0.5×、1×、2×、4×** 之间切换；该倍率只影响播放速度。
- 在历史的“事件与回放定位”区域选择事件，点击定位按钮，打开对应记录快照。

播放器状态与原记录状态分别显示。播放器播放到末尾，不代表原运行一定完成；判断原运行是否完成，应查看记录状态与结果摘要。

回放中的速度是相邻记录区间的平均速度，首个时间组可能显示不可用。回放轨迹仅显示当前位置及以前最多 300 个记录点；倒退定位会清除之后的显示轨迹。播放位置可做平滑显示，暂停和定位时显示保存的快照位置。

如果需要改变参数后重新试验，使用“复制输入新建”，再保存并运行。

## 8. 图像实验

### 8.1 浏览已有结果

“图像实验”页用于读取已有结果，不会从界面启动实验。Git 仓库提供实验程序和配置，**不附带历史实验输出**。首次使用时，先按第 8.2 节生成自己的结果，或使用已有结果目录；尚未产生数据时，该页没有可供分析的历史样本。

1. 进入“图像实验”，选择本地已有的结果目录并载入；也可使用结果目录选择入口打开第 8.2 节生成的目录。
2. 查看按方法、条件汇总的样本数、正确率和处理耗时。
3. 在失败列表按编号、条件或方法筛选。
4. 选择一条失败记录，查看原图、真实标签、结果、原 CSV 行及混淆矩阵。
5. 使用“打开原始预测 CSV”查看逐图结果，必要时打开原图核对。

若保留了此前的本地数据，首批结果位于 `artifacts/marker_experiment/`，多轮结果位于 `artifacts/marker_repeat5/` 下的批次目录。自行执行的实验以 `--output` 指定的目录为准。

独立原图、条件变体和重复调用不是同一个数量。重复多轮不会增加独立原图数；界面中的单次处理耗时也不等于包含读图和作图的总运行时间。

### 8.2 自行执行一次图像实验

此功能使用独立环境，平时只运行仿真或浏览已有结果时无需安装。

```powershell
.\.venv\Scripts\python.exe -m venv .experiment-venv
.\.experiment-venv\Scripts\python.exe -m pip install -r requirements-experiments.txt
```

下面的命令依次准备数据、检查数据、执行实验。使用尚未存在的新目录保存结果；重复操作时换一个目录名，避免覆盖已有结果。

```powershell
.\.experiment-venv\Scripts\python.exe -m marker_experiment generate --config configs/marker_experiment.json --output artifacts/marker_experiment_my_run
.\.experiment-venv\Scripts\python.exe -m marker_experiment verify --config configs/marker_experiment.json --output artifacts/marker_experiment_my_run
.\.experiment-venv\Scripts\python.exe -m marker_experiment run --config configs/marker_experiment.json --output artifacts/marker_experiment_my_run
```

在第一条命令完成后执行第二条，确认检查成功再执行第三条。原始逐图结果保存在 `predictions.csv`，汇总在 `summary.csv`、`summary.json`，图表和数据清单也在该输出目录中。更多命令参数可用 `-m marker_experiment --help` 查看。

## 9. 命令行操作

以下命令仍在项目根目录执行；包含空格的路径使用引号。

### 9.1 打开指定场景

打开工作台并载入基础场景：

```powershell
.\.venv\Scripts\python.exe -m sim_app.workbench --scene configs/basic_scene.json
```

直接打开指定场景的仿真窗口，不经过工作台：

```powershell
.\.venv\Scripts\python.exe -m sim_app --scene configs/detailed_scene.json
```

窗口打开后仍需点击“开始”。自建场景可将 `--scene` 后的路径替换为 `configs/user_scenes/demo_route.json`。

### 9.2 不打开窗口，直接运行并导出

```powershell
.\.venv\Scripts\python.exe -m sim_app --headless --scene configs/basic_scene.json --output-dir artifacts/my_runs
```

该命令自动推进仿真，并在指定父目录下创建独立运行目录。默认最多执行 7200 个逻辑步；确需更长运行时，可增加 `--max-steps`，例如 `--max-steps 36000`。达到步数上限时可能得到未完成记录，应检查结果状态。

要在工作台查看自定义输出目录：

```powershell
.\.venv\Scripts\python.exe -m sim_app.workbench --runs-root artifacts/my_runs
```

### 9.3 打开或检查最新记录

下例选取默认运行目录中最后写入的 `run.json`，再打开回放。若结果保存在其他目录，将命令中的 `artifacts/runs` 替换为对应父目录。

```powershell
$latestRunFile = Get-ChildItem -LiteralPath .\artifacts\runs -Filter run.json -Recurse -File |
    Sort-Object LastWriteTime -Descending |
    Select-Object -First 1

if ($null -eq $latestRunFile) {
    throw '该目录没有运行记录，请先完成一次运行或修改查询目录。'
}

.\.venv\Scripts\python.exe -m sim_app --replay $latestRunFile.FullName
```

在同一个 PowerShell 窗口中，不打开界面检查该记录：

```powershell
.\.venv\Scripts\python.exe -m sim_app --replay-check $latestRunFile.FullName
```

检查成功时输出 `REPLAY_CHECK_OK`，包括快照数、逻辑步数、仿真时间、原记录状态和事件数。它确认记录可读取，是否完成仍以 `source_state` 等结果字段为准。

其他入口参数可执行以下命令查看：

```powershell
.\.venv\Scripts\python.exe -m sim_app --help
.\.venv\Scripts\python.exe -m sim_app.workbench --help
```

## 10. 常见问题

| 问题 | 处理方法 |
| --- | --- |
| 提示找不到 `python` | 确认已安装 Python；有 `py` 启动器时用 `py -3.11 -m venv .venv` 创建环境 |
| 找不到 `.venv\Scripts\python.exe` | 确认当前位于项目根目录，并完成第 1.1 节的环境创建 |
| 提示缺少 `pygame` | 用 `.venv` 的解释器重新执行 `-m pip install -r requirements.txt`，不要安装到另一个 Python 环境 |
| 双击后没有出现窗口 | 在 PowerShell 执行启动命令查看错误，再运行 `--check`；不要只反复双击 |
| 出现 `_tkinter`、`Tcl` 或 `Tk` 错误 | 使用带 Tcl/Tk 的 Python 创建环境；若手工设置过 `TCL_LIBRARY`、`TK_LIBRARY`，检查是否与该解释器匹配 |
| 地图或装备图样缺失 | 检查 `sim_app/assets` 是否完整，恢复缺失文件；不要只复制入口脚本 |
| 打开仿真窗口后单位不动 | 点击“开始”；检查是否暂停、是否存在任务点，或任务是否已完成/受阻 |
| 拖地图时移动了单位 | 编辑器中开启“平移模式”，或从空白位置拖动；运行窗口拖动只改变视图 |
| 地图放大后找不到单位 | 从列表选择单位，点击“定位装备”；需要全图时点击“适应”或“复位” |
| 看不到列表或属性栏 | 点击“恢复面板”，必要时增大窗口 |
| 修改数值后地图未更新 | 点击“应用修改”；确认选中的是要修改的对象，并查看字段错误提示 |
| 校验或保存失败 | 检查重复编号、非法数值、越界坐标和障碍尺寸；修正后重新校验 |
| 历史里没有新记录 | 确认运行已经开始并成功保存，点击“刷新”，核对“更多”中的记录目录，或直接导入 `run.json` |
| 运行结束但任务仍有未完成 | 查看记录的结束原因、受阻原因和事件；时限、步数上限或提前退出都可能留下未完成任务 |
| 全球地图上没有正确定位装备 | 使用带地理参考的场景，或配置并应用地理参考；虚拟坐标不会自动变成经纬度 |
| 图像实验提示缺少图像库 | 执行实验时使用 `.experiment-venv` 并安装 `requirements-experiments.txt`；普通仿真无需这些依赖 |
| 保存提示权限不足或空间不足 | 改用可写且空间足够的目录，修复后重试；原运行窗口提示保存失败时先保留窗口 |

从工作台启动的子窗口日志可在 `artifacts/workbench_logs/` 查看。直接命令行启动的错误会显示在当前终端中。

## 11. 使用范围

- 单位速度、观测范围和交互规则属于二维教学仿真参数，不代表真实装备性能。
- 山区和世界底图用于显示；图中的道路、河流和高程不会自动参与寻路或碰撞。需要通行限制时，在场景中配置障碍。
- 世界底图离线使用，属于小比例尺地图；放大不会获得街道级影像或三维地形。跨日期变更线的地理参考目前不支持。
- 任务完成、受阻、未分配任务和中断记录分别统计，不能只凭播放器到达末尾判断任务成功。
- 较长运行的完整快照可能占用较多存储空间，回放会载入记录；定期备份重要结果并检查输出目录空间。
